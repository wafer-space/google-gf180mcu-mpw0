# Provenance of Google / Efabless GFMPW-0

GFMPW-0 was the first GlobalFoundries GF180MCU shuttle of the Google-sponsored Open MPW program, run by Efabless; the final dies were committed in December 2022. Every project is a [Caravel](https://github.com/efabless/caravel-gf180mcu) die: the user design in `user_project_wrapper` (about 3.0 × 3.0 mm), surrounded by the same management SoC, housekeeping SPI, padframe and power routing on every die.

# How This Repository Was Generated

This repository presents the shuttle in the same format as the [wafer.space](https://wafer.space/) run repositories ([ws-run1](https://github.com/wafer-space/ws-run1), [ws-run2](https://github.com/wafer-space/ws-run2)), so the same tools can analyse it. The reticle in `layout/` is synthetic and is not the mask set as manufactured. It was generated by the wafer.space [reticle-stitcher](https://github.com/wafer-space/reticle-stitcher), the same tool and settings as the ws-run reticles, from the individual final dies published at [https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-000](https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-000):

1. Each 3880×5070 µm Caravel die (top cell renamed `caravel`) was put through the last two steps a wafer.space project gets from LibreLane: dummy fill (COMP, Poly2 and Metal1–5) from the gf180mcuD PDK's `fill_all.rb`, as `KLayout.Filler` does, then the wafer.space 26 µm seal ring from the PDK's `sealring.py`, as `KLayout.SealRing` does, giving a 3932×5122 µm 1×1 slot. The published dies have neither fill nor seal ring; the real GFMPW-0 chips were filled later by Efabless or GF, so this fill is a stand-in for theirs, added so that the renders and density figures can be compared with the wafer.space runs.
2. `reticle_stitcher.py` placed the 40 dies from a 16×10 tile map, wrote `data/manifest.csv`, `images/GFMPW0.svg`, the project table in [README.md](README.md) and `images/GFMPW0.png` (rendered with `scripts/lay2img.py`), and added its own dummy fill to the saw streets between the dies.

The dies keep their arrangement on the real GFMPW-0 reticle, as shown in Efabless's `images/gfmpw-0.png`, where each die lies on its side in 8 rows of 5. Here the whole reticle is turned 90° clockwise so that its long edge is at the top and every die is upright: position A1 is at the top right, A8 at the top left and E1 at the bottom right.

Each die's top cell in the layout is `<CODE>_caravel_<column>_<row>`; the code is the last four hex digits of the Efabless user ID.

# Sources

- Source: the shuttle mirrors at [https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-000](https://foss-eda-tools.googlesource.com/third_party/shuttle/gf180mcu/mpw-000): one repository per slot (`slot-001` ... `slot-040`) plus `foundry`, which holds `manifest-gfmpw-0.csv`, `gfmpw-0.png` (kept here unchanged as `images/gfmpw-0.png`) and the DRC summary.
- Each die is `tapeout/outputs/oas/caravel_<ID>.oas` at the head of `main` in its slot repository. 34 of the 40 match the SHA1 in `manifest-gfmpw-0.csv`. The other six (slots 002, 008, 019, 020, 021 and 029) were updated by Efabless on 2022-12-30 and 2023-01-03 to remove the PR boundary layer (0/0) and the outline shape, the same change the `foundry` repository records as "remove pr boundary for projects"; the manifest SHA1s still refer to the earlier versions. This repository uses the later files.
- None of the 40 dies contain PR boundary (0/0) shapes, including inside the standard cells.
- `SHA256` and `LAYOUT` in `data/manifest.csv` refer to the sealed die files given to the stitcher (`<CODE>/caravel.gds`), which are not published separately; the stitched layout contains them unchanged.
- Repository links point to the designer's GitHub repository where one in a public mirror contains the slot's three newest non-Efabless commits; otherwise to the slot repository at googlesource.
- 39 slot repositories are Apache-2.0 licensed; slot-019 (unigate-gf) is MIT licensed.
